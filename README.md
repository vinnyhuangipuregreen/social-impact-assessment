# SIA 社會影響力評估

依綠色公益基金會《SIMP 系統設計規格書 v1.0》開發的可執行 MVP，涵蓋 **VEGRUN 復蔬公益路跑、世界地球日 × 森林覺醒、綠・蔬食評鑑指南**。前台與管理後台共用 REST API 和資料庫。

## 啟動 Demo

需要 **Node.js 24.12 以上**。先執行 `npm ci` 安裝依賴；照片與證據圖片透過隨程式部署的 sharp 套件處理縮圖、自動轉正及移除中繼資料，不需另外安裝 ImageMagick。

Windows 解壓縮後執行 `START-DEMO.cmd`。也可在本資料夾執行以下指令。

```sh
npm start
```

| 入口 | 網址 |
| --- | --- |
| 活動前台 | http://127.0.0.1:3030/ |
| 管理後台 | http://127.0.0.1:3030/admin |

啟動時依序套用 SQL migration，建立 `var/simp.sqlite`。第一次啟動會為三方案建立相對當日的近期場次、追蹤場次及合成帳號。關閉後再啟動會讀取同一資料庫。Demo 使用模擬簡訊驗證、LINE 授權與 LINE OA，不會發出真實通知。前台活動照片為生成情境圖。

## Vercel 與 Turso

在 Vercel 專案的 Environment Variables 設定以下值，然後重新部署：

| Key | 類型 | 值 |
| --- | --- | --- |
| `TURSO_DATABASE_URL` | Config | `libsql://social-impact-assessment-vinnyhuangipuregreen.aws-ap-northeast-1.turso.io` |
| `TURSO_AUTH_TOKEN` | Secret | 該資料庫具有讀寫權限的 Token |

兩個變數需套用到 Production；若要使用 Preview 部署，也需為 Preview 設定。第一次啟動會依序套用 `migrations/`，建立目前模式的初始資料。Migration 與初始化均使用交易，重啟不會重建或清空既有資料。未設定雲端連線時，本機仍使用 `var/simp.sqlite`；Vercel 則會明確報錯，避免意外將資料寫入暫存目錄。

目前維持 Demo 模式（`SIMP_DEMO=1`，預設），建立示範帳號與活動，不會發出真實簡訊或 LINE 通知。這是新的雲端資料庫初始化，不會自動上傳本機的參與紀錄。正式模式仍需要獨立資料庫及下方列出的正式身分驗證設定。

本機若要連線 Turso，將上述兩個值填入未追蹤的 `.env`，再執行 `npm start`。請勿提交 Token。Vercel 部署會包含 sharp 的平台原生依賴，圖片處理後存入 Turso，仍受原有檔案讀取權限保護。

## 操作方式

### 前台

1. 點「登入／註冊」，輸入示範門號 **0900 000 001**，驗證碼為 **246810**。其他測試門號可體驗新帳號。
2. 在「個人資料」確認個資告知，並按方案設定追蹤同意。佛光會員可選督導區、所屬分會及輸入佛光卡號。非會員也可上傳選填照片。
   居住資料使用「居住縣市 → 居住地區」連動選單。系統管理員可於後台「縣市地區維護」新增、編輯、排序及停用選項；停用保留既有紀錄。舊縣市文字會自動對應，未填地區保持空白；無法對應的舊文字保留供本人重新選擇。
3. 從「活動探索」報名近期場次。前往「我的問卷」填寫活動前問卷，或用示範帳號查看已開放的 90 天追蹤。
4. 「影響力歷程」依場次顯示活動、答卷及可比較的變化。已完成問卷內可查閱回執識別碼，供更正申請使用。

### 管理後台

### 四類標準問卷與手機串接

三個方案共用新版標準題目：基線（T0）、後測（T1B）、3 個月追蹤（T2，約 90 天）、6 個月追蹤（T3，約 180 天）及幹部回饋（STAFF）。基線在報名期間填寫，活動開始即截止；後測為活動結束起 72 小時；追蹤各開放 7 天；幹部回饋為活動後第 7 至 14 天。後台可在草稿場次調整排程。

問卷顯示登入者姓名、已驗證手機遮罩及居住地，不再要求填寫姓名或 Email。各階段使用手機驗證所連結的穩定 participant ID 配對，變更手機仍保留原歷程。基線追蹤同意同步更新該方案追蹤資格；不同意或撤回後不派送追蹤。

在「活動與簽到」開啟草稿場次，按「套用四類標準問卷」建立五個階段（追蹤使用相同題目兩次）。「幹部名單」以已完成登入驗證的手機號碼指定對象，可停用或重新啟用；幹部不需另外報名跑者活動。派送幹部問卷時，對象固定為本場指定幹部。

新版支援單選、複選、整數、小數及文字回饋。四項幹部能力各記錄參加前後的 1–5 分。問卷版本頁可載入標準題目另存草稿並發布；題目變更需新版本。

更新會新增標準版本，將原始標準階段切換至新版供尚未填答者使用；已提交答卷仍依每份答卷保存的原版本檢視、更正及統計，原答案不改寫。場次已指定的自訂版本維持原設定。舊版活動中及 30 天問卷保留為舊版，不作新標準流程。新版全日蔬食四級資料不與原餐數／其他方案舊指標混算；知識基線配對與回溯前測分開列示。新版統計會納入報表、CSV 與成果快照，沿用最小樣本門檻。

| 示範角色 | 可體驗流程 |
| --- | --- |
| 活動營運 | 建立草稿場次、綁定已發布問卷、發布場次、批次簽到、依卡號或非會員條件派送、查回收 |
| 北市北第六區／第三區承辦 | 驗證組織授權範圍 |
| 身分審核、身分複核 | 佛光卡號核驗、衝突案件、資料權利請求、獨立複核 |
| 成果分析、第三區分析 | 篩選配對成效、CSV 匯出、建立證據與快照、以回執識別碼提出更正 |
| 審校發布 | 獨立審核證據、成果快照與問卷回覆更正 |
| 系統管理員 | 全部後台功能、縣市地區維護、帳號權限管理及稽核紀錄 |

「權限管理」可新增後台帳號、指定既有角色與組織範圍、啟用或停用帳號，並記錄異動理由。系統管理員固定管理全平台，且至少須保留一位啟用的系統管理員。角色、範圍或狀態異動會撤銷該帳號既有登入。正式模式仍由驗證服務驗證帳密與 MFA；本機已維護的授權不會被下次登入覆蓋。獨立複核規則適用所有角色，包含系統管理員。

「問卷與版本」每列提供刪除功能，由活動營運、審校發布或系統管理員操作並確認。未被引用的草稿、已發布及已停用版本皆可永久刪除；仍有場次綁定、歷史答卷或成果快照引用時會阻擋並顯示數量，請改用停用。刪除留下稽核，版本號不重用，也不會於重啟時自動重建。

- 在「問卷派送」選 VEGRUN 北區場、T2，依已核驗會員卡號建立名單，可觀察待審、找不到卡號與格式錯誤的排除原因。佛光卡號第一碼為 B，後面接 14 碼數字。
- 在「成效報表」選 VEGRUN 北區場、T2。剛建立的 Demo 資料中，派送回收率為 **4 / 10 = 40%**，T0–T2 配對率為 **3 / 8 = 37.5%**。
- 在「活動與簽到」開啟已發布場次的設定，可複製場次及問卷入口，供印製公用 QR 使用。入口僅包含場次或問卷識別碼。個人通知連結另有到期權杖，登入後核對歸屬。
- 建立成果快照時，選 VEGRUN 北區場的核准證據。以「成果分析」製作，再由「審校發布」複核。快照保存資料截止、篩選、樣本、計算版本與來源。

## 實作與測試

| 路徑 | 內容 |
| --- | --- |
| `web/` | 繁體中文響應式前台與後台。共用 UI 元件、圖像資產及 API 連線 |
| `src/` | TypeScript 原生 Node.js HTTP 服務，含權限、身分、問卷、通知佇列與報表 |
| `migrations/` | SQLite 外鍵、唯一索引、有效答卷、派送嘗試、稽核及版本資料 |
| `tests/` | 合成資料 API 驗收與 5,000 人名單續跑測試 |
| `API.md` | API 與外部服務介接契約 |

```sh
npm test
npm run test:scale
```

API 驗收測試會建立暫存資料庫並自行啟動服務。5,000 人測試約需一分鐘，過程會重啟服務並檢查每個對象的模擬收據。本次驗收中，工作程序重啟後從 87 筆已接受紀錄續跑至 5,000 筆，每位收件人均保有一份管道收據。6 個示範場次的管理列表在 100 個並行請求下量得 p95 179 ms。這是本機合成資料測試。瀏覽器無法連到開發機服務，畫面互動尚未完成瀏覽器驗收。

## 正式試點狀態

- 本交付以規格書 P0 為主，含基本證據、獨立複核快照與回覆更正。完整商家評鑑、SROI、進階公益影響力與減碳估值屬 P1，尚未實作。
- 採用 Node.js 與持久化 SQLite 單節點配置，降低試點安裝門檻。附件存於受權限保護的 SQLite BLOB。規格建議的 PostgreSQL、私有物件儲存、多節點部署及備援未配置。資料庫備份可用 SQLite 備份工具處理 WAL 資料。
- 正式簡訊、LINE/OA、後台 MFA 經介接服務處理。此套件提供呼叫端及契約，尚無基金會憑證，也未執行正式收發驗收。更換正式模式需使用全新資料庫、核定告知文字、環境金鑰及 HTTPS。
- 合成督導區、分會與問卷題幹為開發種子。正式組織名冊、核准題目、保存刪除與無舊門號復原政策由主辦核定。權利請求可收件及追蹤，系統依管理員人工核驗決定後續資料處置。

複製 `.env.example` 為 `.env` 可更換埠號、資料庫路徑與小樣本顯示門檻。日期以 UTC 儲存，前台問卷及營運場次依設定時區顯示。Demo 日期隨首次建立資料庫的時間決定。
